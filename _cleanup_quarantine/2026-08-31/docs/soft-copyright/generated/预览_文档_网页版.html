13
14### 1.1 开发背景
15
16随着大语言模型在客服、办公自动化、知识问答等企业场景的深入应用，业务侧越来越依赖 **Agent（智能体）** 完成多步骤、带工具调用的任务。传统人工抽检无法覆盖回归成本，仅比较最终自然语言答案也难以发现「用错工具、多调工具、中间推理偏离」等问题。
17
18AgentFlow-Eval 针对上述痛点，提供可重复、可追溯、可评分的自动化评测工作台，使研发与测试人员能够以「测试用例」形式固化业务预期，并通过可视化链路与多维分数定位问题。

25- 通过 CSV/JSON 文件批量导入测试用例
26- 生成结构化的评测报告，包含各维度分数分布和详细扣分说明

24本软件是面向企业 AI 应用场景的 **Agent（智能体）自动化评测工作台**。用户可创建评测任务、导入业务测试用例，系统自动调度 Agent 执行，记录完整推理与工具调用轨迹，并结合规则指标与大模型评审（LLM-as-Judge）生成多维评分与结构化报告。
25
26与通用聊天 Demo 或单一 API 封装不同，本软件形成了「用例管理 → 异步执行 → 轨迹可视化 → 混合评分 → 报告与审计」的 **端到端评测闭环**，具有独立的数据处理流程与界面交互设计。

30## 2. 独创性要点（相对通用框架的差异化）
31
32### 2.1 评测领域数据模型与状态机
33
34- 自定义 **Task / TestSuite / Trace / MetricScore / AuditLog** 领域模型及任务状态迁移（创建、排队、运行、完成、失败、取消、归档）。
35- Trace 中结构化保存 ReAct 步骤、token、耗时及版本元数据（agent/prompt/model/tool version），支撑评测可追溯。
36
37### 2.2 Agent 执行与工具沙箱一体化
38
39- 抽象 `BaseAgentRunner`，实现 OpenAI 兼容 **ReAct 多轮执行器**。
40- 内置 **工具沙箱**（超时控制、工具列表探测），将工具调用结果写回轨迹，而非仅保存最终自然语言回复。
41
42### 2.3 混合评分引擎（规则 + LLM-as-Judge + 人工复核）
43
44- `metrics` 模块实现无 LLM 的轻量规则分（如工具集合准确率、答案抽取）。
45- `LLMJudge` 在规则分基础上调用大模型进行多维语义评分并生成扣分说明。
46- 支持 **人工审核覆盖评分**，形成机评与人评结合的质检流程。
47
48### 2.4 异步评测流水线
49
50- 基于 Celery + Redis 的 `run_full_evaluation` 全流程任务：逐条执行用例、落库轨迹、自动评判、更新任务状态。
